# Olea — Reference for LLMs / Agents

Purpose of this file: hand a future session (or subagent) everything needed to keep building
Olea without re-deriving context. Read this first, then the code. Where this file and the code
disagree, the code wins.

---

## 1. What this repo is

Two independent, local-only web tools for running a TTRPG campaign. Plain JavaScript everywhere
(NO TypeScript). Both are Vue 3 SFCs with `<script setup>`.

| App | Backend | Frontend | Port | Start script |
|---|---|---|---|---|
| Inventory & money manager | PocketBase v0.40.4 (single binary, SQLite, realtime) | `inventory/` (Vue 3 + Vite + Pinia + Vue Router) | **8090** | `./inventory/start.sh` |
| Soundboard | `soundboard/server.js` (Express, no DB) | `soundboard/` (Vue 3 + Vite, no router/pinia) | **8091** | `./soundboard/start.sh` |

The inventory app works on any phone browser. The soundboard uses Web MIDI and is meant for the
GM's laptop.

## 3. Inventory app (PocketBase + Vue)

### 3.1 Data model (collections, from `inventory/pb_migrations/1791200000_init.js`)

Custom collection ids: `w_players`, `w_systems`, `w_games`, `w_currencies`, `w_memberships`,
`w_wallets`, `w_items`, `w_inventory`.

- **players** (type `auth`): `name` (text, required, unique index). System email/password fields
  exist but are auto-generated and hidden; identity is name-only. `authRule = ""` (allow any).
  `listRule`/`viewRule` = `"@request.auth.id != ''"`; create/update/delete = `""` (only via `/api/login`).
- **systems** (shared catalogs): `name` (required, unique), `description`, `weight_unit`
  (`select`: `lb|kg`). Any global GM may create/edit/delete.
- **games**: `system` (rel→systems, cascadeDelete **false**, required), `name` (required),
  `description`. Reads = auth; writes = `""` (only via `/api/games`).
- **currencies** (belong to a system): `system` (rel→systems, cascade), `name` (required),
  `symbol`, `base_value` (int, required, min 1), `sort`. Unique `(system, name)`.
- **memberships**: `game` (rel, cascade), `player` (rel→players, cascade), `role` (`select`,
  `gm|player`, required). Unique `(game, player)`. A GM has no wallet or inventory in that game.
- **wallets**: `game` (rel, cascade), `membership` (rel→memberships, cascade), `currency`
  (rel→currencies, **no cascade**), `amount` (int, min 0, **NOT required** — see gotcha §3.3),
  `location` (`select`: `person|stash`, required). Unique `(membership, currency, location)`.
- **items** (system catalog): `system` (rel→systems, cascade), `name` (required), `category`,
  `kind` (`select`: `single|stack|charges`, required), `max_charges`, `weight`, `value`,
  `value_currency` (rel→currencies, no cascade), `description`, `image` (`file`, maxSelect 1,
  images only). create/update/delete require a **global GM**; `value_currency` must belong to the
  item's system.
- **inventory** (owned instance): `game` (rel, cascade), `item` (rel→items, cascadeDelete
  **false**), `owner` (rel→players, cascade), `quantity` (int, stack kind), `charges_current`
  (int, charges kind), `location` (`person|stash`).

Semantics:
- **Global GM** = an account whose membership role is `gm` in at least one game. Systems,
  currencies and catalog items are shared between all GMs.
- `kind`: `single` = no qty/charges; `stack` = uses `quantity`; `charges` = uses
  `charges_current`/`max_charges`.
- Items live either on `person` (pocket) or in the player's `stash`. Transfers always arrive on
  `person`.
- Deleting a game cascades its memberships, wallets and inventory; it does **not** delete the
  system, its currencies or its items.
- Deleting a system is blocked while any game uses it; its currencies/items cascade when it is
  deleted. Deleting a currency is blocked while wallets or catalog items reference it. Deleting a
  catalog item is blocked while inventory holds it.
- Money is per-denomination integers; there is no cross-currency conversion on transfer. The
  "optimized total" (fewest coins) is computed client-side in `inventory/src/utils/money.js`.
- Weight is per-system (`lb` or `kg`); totals (weight × quantity for stacks) are computed in
  `inventory/src/utils/weight.js`.

### 3.2 Backend routes (all in `inventory/pb_hooks/main.pb.js`)

All except `/api/login` require `$apis.requireAuth("players")` (auth token → `e.auth`).

- `POST /api/login` — body `{name}`; find-or-create player by name, return `recordAuthResponse`
  (standard `{token, record}`).
- `POST /api/games` — `{name, description?, systemId}` **or**
  `{name, description?, newSystem:{name, description?, weight_unit?, currencies, items?}}`.
  Creates game + GM membership; inline system creation bypasses the global-GM requirement so a
  new account can bootstrap itself. At least one currency is required for an inline system.
- `DELETE /api/games/{id}` — GM-only hard delete (game data cascades).
- `POST /api/members` — `{game, playerName, role?}`; GM adds/find-or-creates player.
- `DELETE /api/members/{id}` — GM removes membership; also deletes that player's inventory in the
  game (wallets cascade via membership). Cannot remove the last GM.
- `POST /api/members/{id}/role` — `{role}`; GM sets role. Cannot demote the last GM or promote a
  player who still holds items/money in the game.
- `POST /api/inventory/give` — `{game, toPlayerId, itemId?, inventoryId?, quantity?}`.
  `itemId` → GM grants a catalog item (quantity only for stack). `inventoryId` → transfer existing
  entry (owner or GM; quantity splits a stack). Recipients must be players; transfers land on
  `person`.
- `POST /api/inventory/use` — `{inventoryId}`; owner only; decrements `charges_current` for charges
  or consumes one unit of a stack (entry is deleted at 0).
- `POST /api/inventory/drop` — `{inventoryId, quantity?}`; owner or GM. GM "take" deletes the whole
  instance; an owner may drop part of a stack.
- `POST /api/inventory/move` — `{inventoryId, location, quantity?}`; owner only; moves person/stash;
  quantity splits a stack and merges into an existing stack at the destination.
- `POST /api/money/give` — `{game, toPlayerId, currencyId, amount, location?}`; player→player
  transfer. Source defaults to `person`; destination is always `person`.
- `POST /api/money/gm` — `{game, playerId, currencyId, amount, location?}`; GM give (+) or take
  (−) at the chosen location.
- `POST /api/money/move` — `{game, currencyId, amount, from, to}`; player moves own money between
  person/stash.
- `POST /api/systems/{id}/import` — global GM JSON import of `{currencies?, items?}`; upserts
  currencies by name and items by `(system, name)`.

Record hooks:
- systems/currencies/items create/update/delete require a global GM.
- system delete blocked while games use it.
- currency delete blocked when wallets or items reference it.
- item delete blocked while inventory holds it; item `value_currency` must match the item's system.

Role helpers (`membershipOf`, `roleOf`, `requireMember`, `requireGM`, `requirePlayer`,
`isGlobalGM`, `requireGlobalGM`, `playerByName`, `ensureWallet`, `adjustWallet`,
`createInventoryEntry`, `currencyLookup`, `importSystemData`, `validateItemCurrency`, `createSystem`)
live in `inventory/pb_hooks/utils.js`.

### 3.3 PocketBase JSVM gotchas (CRITICAL for any backend change)

1. **Handlers run in isolated contexts.** Top-level `function`/`const`/`var` in a `.pb.js` file are
   NOT visible inside a handler. Share logic via a CommonJS module and `require()` it INSIDE the
   handler: `const u = require(__hooks + "/utils.js")`. Even a top-level `const UTILS = "..."` is
   invisible in handlers — inline the string.
2. **`findFirstRecordByFilter` throws `"sql: no rows in result set"`** when nothing matches (doesn't
   return null). Wrap it (see `firstOrNull` in `utils.js`). `findRecordById` also throws on miss.
3. **Record request hooks must call `e.next()`** or the operation silently no-ops (200, empty body).
4. **`required: true` on a NumberField treats `0` as blank** (validation error). Don't mark a number
   field required if `0` is a valid value (why `wallets.amount` is not required).
5. Path params: route `{id}` → `e.request.pathValue("id")` (NOT `e.pathValue`).
6. Custom auth: `return $apis.recordAuthResponse(e, record, "", {})` writes `{token, record}`.
7. Error types: `throw new BadRequestError(msg, {})`, `ForbiddenError`, `NotFoundError`, `ApiError(status,msg,data)`.
8. Globals: `$app` (find/save/delete/runInTransaction), `$apis` (requireAuth, recordAuthResponse,
   static), `$os` (getenv, readDir, dirFS, getwd), `$security` (randomString, etc.),
   `$filesystem`, `Record` (constructor), `Collection`/`new Collection`, field classes
   (`TextField`, `NumberField`, `RelationField`, `SelectField`, `FileField`, …). Full types in
   `inventory/pb_data/types.d.ts` (generated).
9. Transactions: `app.runInTransaction((tx) => { ... })` — use `tx` for all reads/writes inside.
10. `e.auth` is the authenticated record; `e.auth.get("id")`, `e.auth.get("name")` (use `.get()`,
    not `.id`, to be safe).

### 3.4 Frontend (`inventory/`)

- `src/pb.js` — `new PocketBase('/')` (relative; Vite proxies `/api` in dev, PocketBase serves the
  built app in prod).
- `src/api.js` — thin `pb.send()` wrappers for the custom routes above (JSON body, stringified).
- `src/stores/auth.js` — `player`, `login(name)`, `logout()`, `init()` (restore from `pb.authStore`).
- `src/stores/game.js` — the main store. State: `games`, `activeGame`, `system`, `systems`,
  `currencies`, `members`, `items`, `inventory`, `wallets`, `loading`. Getters: `myPlayerId`,
  `myMembership`, `role`, `isGM`, `isGlobalGM`, `currencyMap`, `itemMap`, `categories`, `players`,
  `gms`, `inventoryFor(playerId, location?)`, `walletFor(playerId)` (→ `{person, stash}`, each
  `{raw, amounts, total, optimized}`). Actions: game flows (`loadGames`, `createGame`,
  `openGame`, `closeGame`, `deleteGame`), systems (`loadSystems`, `openSystem`, `closeSystem`,
  `createSystem/updateSystem/deleteSystem`, `createCurrency/updateCurrency/deleteCurrency`,
  `importSystem`), catalog items (`createItem/updateItem/deleteItem` on the active system),
  members (`addMember/removeMember/setRole`), inventory (`giveItem/useItem/dropItem/moveItem`),
  money (`giveMoney/gmMoney/moveMoney`).
  Realtime: on open, subscribes to `currencies/items` filtered by `system = id` and
  `memberships/inventory/wallets` filtered by `game = id`, refetching that collection on any event.
- Views: `HomeView` (name login), `GamesView` (Games I run / Games I play + create with existing or
  inline system), `SystemsView` (`/systems`), `SystemView` (`/systems/:id`, currency/item/import
  tabs), `GameView` (GM: players-only selector + Inventory/Money/Members/Catalog; player:
  Inventory/Money/Members; delete game), `PrintView` (`/game/:id/print/:playerId`).
- Components: `InventoryPanel` (person/stash + weight), `WalletPanel` (person/stash + transfers),
  `MembersPanel` (GMs/players split), `ItemsPanel` (catalog; reusable with `:show-give="false"`),
  `ItemEditorModal`, `Toast`.
- `src/utils/money.js`: `walletTotal(amounts, currencies)`, `optimizeAmounts(...)` (greedy),
  `currencyLabel`, `formatAmount`. `src/utils/weight.js`: `entryWeight`, `totalWeight`,
  `formatWeight`. `src/utils/errors.js`: `errorMessage(err)`.
  `src/composables/useToast.js`: global toast.
- Build: `cd inventory && npm run build` → `inventory/pb_public/`. Dev: `npm run dev` (proxies
  `/api` → 8090).
- `inventory/CONTRACT.md` documents the store API for the view components.

## 4. Soundboard app (Express + Vue)

Fully separate from PocketBase (no DB — it only serves JSON state files + audio). Port **8091**.
State is **schema v2** JSON only: one `config.json` per scene folder, one app-level `library.json`,
and one `global.json`. The normalizers live in `soundboard/lib/schema.js` (shared by server and
frontend) and the format is documented in `soundboard/SCHEMA.md`. Syrinscape XML is an **import
format only** (read by `soundboard/import.js`). Scenes use **includes** to reference reusable
library groups; `lib/resolve.js` resolves them for the UI and audio engine.

### 4.1 `soundboard/server.js` (Express, ESM, port 8091)

- `GET /api/library` — scan scenes + read app state → `{ soundsets, library, global }`. Scenes are
  normalized configs plus `dir` (path relative to the audio root, `/`-separated). Sorted by name.
  Cached in-process; invalidated on any write.
- `GET /api/files` — editor picker index with file sizes. Scene top-level folders plus **recursive**
  library folders under `_library` → `{ folders: [{ dir, name, files: [{name,file,size}] }] }`.
- `GET /api/soundset/:id` — one scene (`{ ...config, dir: id }`); `:id` is the scene `dir`
  (URL-encoded). 404 if missing.
- `POST /api/soundset/:id` — write a full normalized config; creates the folder if missing →
  `{ ok, soundset }`.
- `DELETE /api/soundset/:id` — recursively delete the scene folder (config + audio) → `{ ok }`.
- `GET /api/global` / `POST /api/global` — read/write `global.json` (buses, palette, global MIDI).
- `POST /api/library` — write `library.json` (the read side is part of `GET /api/library`).
- `POST /api/library/promote` — body `{ soundsetDir, elementId, category }`; copies the element's
  files into `_library/<category>/<slug>/`, writes a library group, replaces the scene element with
  an include, and returns `{ ok, soundsets, library, global, soundset, group, warnings }`. Failure
  codes: `already-library`, `invalid-category`, `missing-file`, `unsafe-path`, `not-found`.
- `GET /api/refs` — `{ ok, broken: [...] }` reference check for missing files/library groups.
- `GET /audio/*` — `express.static(AUDIO_DIR)` (native Range support for seeking).
- Serves `soundboard/dist/` (built frontend) with SPA fallback for non-`/api`/`/audio` GETs.
- `resolveSoundsetDir(id)` rejects empty/absolute ids and any path outside `OLEA_AUDIO_DIR` (or
  inside `_library`) for GET/POST/DELETE. Promotion and file paths use the same guards.

Env: `OLEA_AUDIO_DIR` (default `soundboard/syrinscape`), `OLEA_GLOBAL_FILE` (default
`soundboard/global.json`), `OLEA_LIBRARY_FILE` (default `soundboard/library.json`),
`OLEA_LIBRARY_DIR` (default `<audio>/_library`), `PORT` (default 8091).

### 4.2 Data model

Scene `config.json` (one per scene folder under `soundboard/syrinscape/`):

```jsonc
{
  "version": 2,
  "id": "uuid",                 // stable; renames/disable never change it
  "name": "Car Chase 2017",
  "disabled": false,
  "elements": [ { "id": "uuid", "name", "kind": "loop|random|oneshot", "gain",
    "randomise": "shuffle|random|null", "reverb": "preset|null", "position": null,
    "files": ["Foo.ogg"], "trigger": {"min","max","startMin","startMax"} } ],
  "includes": [ { "id": "instance-uuid", "libraryId": "group-uuid",
    "overrides": { "gain": null, "kind": null, "trigger": null, "reverb": null,
      "randomise": null } } ],
  "hidden": ["instanceUuid"],
  "moods": [ { "id": "uuid", "name", "params": { "<instanceId>": {"plays", "volume"} } } ],
  "midi": { "notes": {}, "ccs": {} },
  "reviewed": true               // false for heuristic imports with no real XML
}
```

- `elements[]` are scene-local; `includes[]` reference reusable groups from `library.json` by
  `libraryId`. Each include has its **own instance `id`**; `overrides` fields with `null` inherit from
  the library group. Resolution lives in `lib/resolve.js`; missing groups are skipped and reported.
- Scene `files[]` are relative to the scene folder (`"Foo.ogg"` or `"../Other/Foo.ogg"`). Resolved
  includes get `baseDir: "_library"` and files relative to the library root. Runtime-only fields are
  `source` (`scene|library`), `baseDir`, and `libraryId` on resolved instances.
- `kind`: `loop` = continuous playlist; `random` = auto-triggered at `trigger` interval; `oneshot` =
  manual. All gains/volumes clamp to `0..1`. `reverb` is a preset from `REVERB_PRESETS` (or `null`);
  `position` is stored but not rendered. Random elements always get a nonzero default trigger
  (`10–30s`, start `2–10s`) if none is configured.
- `moods` are authoritative while active: a loop/random missing from a mood's `params`, or with
  `plays: false`, does not play. Stop keeps the mood selected; Start restores it.

`library.json` (gitignored, at `soundboard/library.json`):

```jsonc
{
  "version": 2,
  "groups": [ { "id": "uuid", "name": "Dogs", "kind": "random", "gain": 0.8,
    "randomise": null, "reverb": null, "position": null,
    "files": ["monsters/dogs/1.ogg"], "trigger": {"min","max","startMin","startMax"},
    "category": "Monsters/Dogs", "tags": ["dog", "bark"] } ]
}
```

`library.groups` is an **array**; lookup is always by group `id`. Group files are relative to
`_library`. Promotion preserves the scene instance id, creates the group, rewrites file paths, and
replaces the element with an include.

`global.json` (gitignored, at `soundboard/global.json`):

```jsonc
{
  "version": 2,
  "buses": { "loop": 1, "random": 1, "effects": 1 },
  "palette": [ { "id": "uuid", "libraryId": "group-uuid", "label": "", "gain": null, "order": 0 } ],
  "midi": { "notes": {}, "ccs": {} }
}
```

`master` volume is session-only (in-memory, default 0.8), never persisted. Palette gains are optional
overrides; `null` inherits the library group gain.

Import: `node soundboard/import.js [folder]` reads a Syrinscape pack (XML + audio) and writes
`config.json`; no arg imports every folder lacking one. A folder with a single XML → one scene; a
folder with multiple chapter XMLs → a container whose chapters each get a subfolder + `config.json`
with `../` file references. Never overwrites an existing `config.json`. Real XML keeps authoritative
kinds/triggers (`reviewed: true`); XML-less packs use `lib/heuristics.js` with file sizes, get a
nonzero random trigger, and are marked `reviewed: false`. Migration sets the same flags from the
presence of real (non-`.generated`) XML.

### 4.3 Frontend modules (`soundboard/src/`)

- `engine.js` — Web Audio. Reactive `state = { activeLoops, loading, activeOneshots }`. Loop elements
  cycle a multi-file playlist with crossfade; one-shots are tracked so they can be stopped. Three bus
  gains + master, plus a **reverb send**: lazily-created `ConvolverNode` per preset, shared return
  gain, per-element dry/wet. Impulse responses are generated programmatically. Supports live one-shot
  gain (`setOneShotGain`) and click-avoiding volume ramps.
- `store.js` — single `reactive` state + actions + MIDI dispatch. State: `soundsets`, `library`,
  `global`, `files`, `activeId`, `activeMoodId`, `masterVolume` (session-only), `volumeOverrides`
  (keyed `${soundsetId}::${elementId}`), `learning`, `loopsPlaying`, `randomsPlaying`,
  `midiConnected`, `midiError`. Resolved-element helpers (`resolvedSceneElements`,
  `soundsetElements`, `findElement`, `paletteElements`) come from `lib/resolve.js`, so library edits
  are reflected immediately. Volume baseline = active mood's param ?? resolved `el.gain`. Actions:
  transport, element play/stop, volumes, mood CRUD/apply (`applyMood` starts/stops to match the mood),
  scene CRUD, library CRUD, palette pin/play/unpin/volume, promotion, include add/remove,
  merge/reclassify, review flag, MIDI learn + dispatch. Local scene bindings override global on the
  same key; global palette mappings report when shadowed. Random elements use `setTimeout` schedulers
  (first fire after `startMin..startMax`, then every `min..max`; zero triggers fall back to defaults).
  Persists via `POST /api/soundset/:dir`, `POST /api/library`, `POST /api/global`, and promotion API.
- `midi.js` — Web MIDI wrapper (`connectMidi`, `onMidiMessage`).
- `App.vue` — topbar (main volume, STOP, MIDI), tabs **Scenes / Library / Review**, active-scene tab,
  and the persistent collapsible palette.
- `components/` — `ScenesPanel` (search, counts, needs-review badge, start/edit/disable/delete,
  Disabled section); `SoundsetPanel` (transport, moods, bus volumes + MIDI learn, Loops/Random/Effects,
  edit bar, hidden elements); `ElementRow` (play/stop, kind/origin/reverb tags, volume reset, learn
  note/CC, edit/promote/pin); `GroupEditor` (kind/volume/interval/reverb + searchable file picker with
  sizes, read-only files for library includes); `MoodEditor` (all resolved loops/randoms);
  `LibraryBrowser` (search/kind filter, preview, add to scene, pin, edit/delete);
  `PalettePanel` (play/toggle, volume, learn note/CC, unpin, missing/shadow warnings);
  `ReviewPanel` (heuristic scenes, element table with size/interval, bulk kind/interval/reverb, merge,
  promote, mark reviewed).

### 4.4 MIDI mapping (stored in `config.json.midi` + `global.json.midi`)

Keys are `"channel:note"` / `"channel:cc"` strings. Local bindings live in a scene's
`config.json.midi`; global bindings live in `global.json.midi`. Local overrides global on the same
key; the palette UI warns when a global mapping is shadowed by the active scene.

- Local notes: `{type:'oneshot'|'loop'|'random', elementId}`, `{type:'mood', moodId}`,
  `{type:'soundset'}`. The element `type` is informational — dispatch uses the element's **current**
  kind, so reclassified elements keep working. Local CCs: `{type:'element', elementId}` (volume).
- Global notes: `{type:'stop'}`, `{type:'soundset', soundsetId}`, `{type:'palette', paletteId}`.
  Global CCs: `{type:'master'}`, `{type:'bus', bus:'loop'|'random'|'effects'}`,
  `{type:'paletteVolume', paletteId}`.
- Re-learning a target replaces its previous key; element-note actions are matched by element id
  even if the stored kind changed.

### 4.5 Web MIDI caveats

- Requires a **secure context**: open via `http://localhost:8091` (not the LAN IP) or HTTPS.
  `connectMidi()` checks `window.isSecureContext` and surfaces a hint.
- Chrome/Edge: works out of the box. Firefox: `about:config` → `dom.webmidi.enabled=true`
  (Web MIDI isn't fully shipped in stable Firefox; Chrome/Edge is the reliable fallback).
- MPK Mini: pads send notes on channel 10, keys on channel 1, knobs send CC. "Learn mode"
  captures whatever channel/note/CC arrives, so no hardcoding needed.

### 4.6 Soundboard build/run

```bash

OLEA_AUDIO_DIR=/other/folder ./soundboard/start.sh
```

## 6. Agent/LLM operational notes (things that bit us)

- **Do not `pkill -f "<string>"`** — the pattern matches the running shell's own command line and
  kills it. Use `pkill -x pocketbase` / `pkill -x node`, or `fuser -k PORT/tcp`.
- Backgrounding long-running servers in the bash tool hangs the tool until timeout. Use
  `nohup CMD </dev/null >log 2>&1 &`, then curl-test in the SAME command, then kill with
  `fuser -k PORT/tcp`. Don't rely on the process surviving across separate tool calls.
- PocketBase binary: v0.40.4, downloaded to `inventory/`, re-fetch via
  `inventory/download-pocketbase.sh`.
- The inventory frontend build uses `emptyOutDir` — `inventory/vite.config.js` writes to
  `./pb_public`. The soundboard builds to its own `soundboard/dist` (no conflict).
- `soundboard/syrinscape/` (~292MB) and runtime dirs (`inventory/pb_data/`, `soundboard/dist/`,
  `soundboard/node_modules/`, `soundboard/global.json`, `soundboard/library.json`,
  `soundboard/_library` audio under the tree, `inventory/pocketbase`) are gitignored. Imported
  `config.json` files live inside `soundboard/syrinscape/` (also gitignored).
- The soundboard does not generate XML at runtime. Run `node soundboard/import.js` (once) to turn
  existing Syrinscape packs into `config.json` files; it is idempotent (never overwrites). Re-run
  `migrate-v2.js` only for legacy v1 data; it is safe to inspect with `--dry-run`.
