# Olea — Reference for LLMs / Agents

Purpose of this file: hand a future session (or subagent) everything needed to keep building
Olea without re-deriving context. Read this first, then the code. Where this file and the code
disagree, the code wins.

---

## 1. What this repo is

Two independent, local-only web tools for running a TTRPG campaign. Plain JavaScript everywhere
(NO TypeScript). Both are Vue 3 SFCs with `<script setup>`.

| App | Backend | Frontend | Port | Start script |
|---|---|---|---|---|
| Equipment & money manager | PocketBase v0.40.4 (single binary, SQLite, realtime) | `equipment/frontend/` (Vue 3 + Vite + Pinia + Vue Router) | **8090** | `./equipment/start.sh` |
| Soundboard | `soundboard/server.js` (Express, no DB) | `soundboard/` (Vue 3 + Vite, no router/pinia) | **8091** | `./soundboard/start.sh` |

The equipment app works on any phone browser. The soundboard uses Web MIDI and is meant for the
GM's laptop.

## 3. Equipment app (PocketBase + Vue)

### 3.1 Data model (collections, from `equipment/pb_migrations/1791200000_init.js`)

Custom collection ids: `w_players`, `w_games`, `w_currencies`, `w_memberships`, `w_wallets`,
`w_items`, `w_inventory`.

- **players** (type `auth`): `name` (text, required, unique index). System email/password fields
  exist but are auto-generated and hidden; identity is name-only. `authRule = ""` (allow any).
  `listRule`/`viewRule` = `"@request.auth.id != ''"`; create/update/delete = `""` (only via `/api/login`).
- **games**: `name` (required), `description`. Reads = auth; writes = `""` (only via `/api/games`).
- **currencies**: `game` (rel→games, cascade), `name` (required), `symbol`, `base_value`
  (int, required, min 1 — value of 1 unit in the game's smallest unit), `sort`.
- **memberships**: `game` (rel), `player` (rel→players, cascade), `role` (`select`, `gm|player`,
  required). Unique `(game, player)`. This is the per-game role + wallet anchor.
- **wallets**: `membership` (rel→memberships, cascade), `currency` (rel→currencies, cascade),
  `amount` (int, **NOT required** — see gotcha §3.5). Unique `(membership, currency)`.
- **items** (catalog, shared): `game` (rel, cascade), `name` (required), `category`, `kind`
  (`select`: `single|stack|charges`, required), `max_charges`, `weight`, `value`,
  `value_currency` (rel→currencies), `description`, `image` (`file`, maxSelect 1, images only).
  create/update/delete rules = `"@request.auth.id != ''"` with GM enforcement in record hooks.
- **inventory** (owned instance): `game` (rel, cascade), `item` (rel→items, cascadeDelete **false**),
  `owner` (rel→players, cascade), `quantity` (int, stack kind), `charges_current` (int, charges kind).

Semantics:
- `kind`: `single` = no qty/charges; `stack` = uses `quantity`; `charges` = uses `charges_current`/`max_charges`.
- Inventory **references** the catalog item (editing an item fixes typos everywhere). Deleting a
  catalog item is blocked while any inventory holds it (see record hooks).
- Money is per-denomination integers; there is no cross-currency conversion on transfer. The
  "optimized total" (fewest coins) is computed client-side in `equipment/frontend/src/utils/money.js`.

### 3.2 Backend routes (all in `equipment/pb_hooks/main.pb.js`)

All except `/api/login` require `$apis.requireAuth("players")` (auth token → `e.auth`).

- `POST /api/login` — body `{name}`; find-or-create player by name, return `recordAuthResponse`
  (standard `{token, record}`).
- `POST /api/games` — `{name, description?, currencies:[{name,symbol,base_value,sort?}]}`; creates
  game + currencies + creator as GM (transaction).
- `POST /api/members` — `{game, playerName, role?}`; GM adds/find-or-creates player.
- `DELETE /api/members/{id}` — GM removes membership; also deletes that player's inventory in the
  game (wallets cascade via membership).
- `POST /api/members/{id}/role` — `{role}`; GM sets role.
- `POST /api/inventory/give` — `{game, toPlayerId, itemId?, inventoryId?, quantity?}`.
  `itemId` → GM grants a catalog item (quantity only for stack). `inventoryId` → transfer existing
  entry (owner or GM; quantity splits a stack).
- `POST /api/inventory/use` — `{inventoryId}`; owner or GM; decrements `charges_current` (blocked at 0).
- `POST /api/inventory/drop` — `{inventoryId}`; owner or GM; deletes.
- `POST /api/money/give` — `{game, toPlayerId, currencyId, amount}`; player→player transfer.
- `POST /api/money/gm` — `{game, playerId, currencyId, amount}`; GM give (+) or take (−).

Record hooks (tagged `"items"`):
- `onRecordCreateRequest` / `onRecordUpdateRequest` — enforce GM of the item's game, then `e.next()`.
- `onRecordDeleteRequest` — GM + block if `inventory.item = id` exists ("take it away first"), then `e.next()`.

Role helpers (`membershipOf`, `roleOf`, `requireMember`, `requireGM`, `playerByName`,
`ensureWallet`, `adjustWallet`, `createInventoryEntry`) live in `equipment/pb_hooks/utils.js`.

### 3.3 PocketBase JSVM gotchas (CRITICAL for any backend change)

1. **Handlers run in isolated contexts.** Top-level `function`/`const`/`var` in a `.pb.js` file are
   NOT visible inside a handler. Share logic via a CommonJS module and `require()` it INSIDE the
   handler: `const u = require(__hooks + "/utils.js")`. Even a top-level `const UTILS = "..."` is
   invisible in handlers — inline the string.
2. **`findFirstRecordByFilter` throws `"sql: no rows in result set"`** when nothing matches (doesn't
   return null). Wrap it (see `firstOrNull` in `utils.js`). `findRecordById` also throws on miss.
3. **Record request hooks must call `e.next()`** or the operation silently no-ops (200, empty body).
4. **`required: true` on a NumberField treats `0` as blank** (validation error). Don't mark a number
   field required if `0` is a valid value (why `wallets.amount` is not required).
5. Path params: route `{id}` → `e.request.pathValue("id")` (NOT `e.pathValue`).
6. Custom auth: `return $apis.recordAuthResponse(e, record, "", {})` writes `{token, record}`.
7. Error types: `throw new BadRequestError(msg, {})`, `ForbiddenError`, `NotFoundError`, `ApiError(status,msg,data)`.
8. Globals: `$app` (find/save/delete/runInTransaction), `$apis` (requireAuth, recordAuthResponse,
   static), `$os` (getenv, readDir, dirFS, getwd), `$security` (randomString, etc.),
   `$filesystem`, `Record` (constructor), `Collection`/`new Collection`, field classes
   (`TextField`, `NumberField`, `RelationField`, `SelectField`, `FileField`, …). Full types in
   `equipment/pb_data/types.d.ts` (generated).
9. Transactions: `app.runInTransaction((tx) => { ... })` — use `tx` for all reads/writes inside.
10. `e.auth` is the authenticated record; `e.auth.get("id")`, `e.auth.get("name")` (use `.get()`,
    not `.id`, to be safe).

### 3.4 Frontend (`equipment/frontend/`)

- `src/pb.js` — `new PocketBase('/')` (relative; Vite proxies `/api` in dev, PocketBase serves the
  built app in prod).
- `src/api.js` — thin `pb.send()` wrappers for the custom routes above (JSON body, stringified).
- `src/stores/auth.js` — `player`, `login(name)`, `logout()`, `init()` (restore from `pb.authStore`).
- `src/stores/game.js` — the main store. State: `games`, `activeGame`, `currencies`, `members`,
  `items`, `inventory`, `wallets`, `loading`. Getters: `myPlayerId`, `myMembership`, `role`,
  `isGM`, `currencyMap`, `itemMap`, `categories`, `inventoryFor(playerId)`, `walletFor(playerId)`
  (→ `{raw, amounts, total, optimized}`). Actions: `loadGames`, `createGame`, `openGame`,
  `closeGame`, `addMember/removeMember/setRole`, `createItem/updateItem/deleteItem` (standard
  record API — supports image upload), `giveItem/useItem/dropItem`, `giveMoney/gmMoney`.
  Realtime: on `openGame`, subscribes to `currencies/memberships/items/inventory/wallets`
  filtered by `game = id` and refetches that collection on any event.
- Views: `HomeView` (name login), `GamesView` (list + create with currency presets DnD/Numenera/CoC/custom),
  `GameView` (tabs Inventory/Money/Members/Items + GM "viewing player" selector),
  `PrintView` (`/game/:id/print/:playerId`, printable sheet).
- Components: `InventoryPanel`, `WalletPanel`, `MembersPanel`, `ItemsPanel`, `ItemEditorModal`, `Toast`.
- `src/utils/money.js`: `walletTotal(amounts, currencies)`, `optimizeAmounts(...)` (greedy),
  `currencyLabel`, `formatAmount`. `src/utils/errors.js`: `errorMessage(err)`.
  `src/composables/useToast.js`: global toast.
- Build: `cd equipment/frontend && npm run build` → `equipment/pb_public/`. Dev: `npm run dev` (proxies `/api` → 8090).
- `equipment/frontend/CONTRACT.md` documents the store API for the view components.

## 4. Soundboard app (Express + Vue)

Fully separate from PocketBase (no DB — it only serves files + a tiny mapping JSON). Port **8091**.

### 4.1 `soundboard/server.js` (Express, ESM, port 8091)

- `GET /api/library` — scans `OLEA_AUDIO_DIR` (default `soundboard/syrinscape`) → `{soundsets:[...], overlay}`.
- `GET /api/files` — full file index for the editor's picker → `{folders:[{dir,name,files:[{name,file}]}]}`.
- `POST /api/library` — save the user overlay (`OLEA_LIBRARY_FILE`, default `soundboard/library.json`).
- `GET /api/mapping` / `POST /api/mapping` — MIDI mapping JSON (`OLEA_MAPPING_FILE`, default `soundboard/midi-mapping.json`).
- `GET /audio/{soundset}/{file}` — `express.static(AUDIO_DIR)` (native Range support).
- Serves `soundboard/dist/` (built frontend) with SPA fallback for non-`/api`/`/audio` GETs.

Audio model (differs from older versions): each top-level folder is scanned for `.ogg`/`.mp3`/`.wav`
files plus `.xml` files. Each XML → one soundset (`id = "<folder>::<xmlBasename>"`); a folder with no
XML → one soundset generated from filename heuristics (`id = "<folder>"`), and a `<folder>.generated.xml`
is written to disk if missing. `soundboard/xml.js` holds the parser (`parseXml`, `parseSoundsetXml`) and the
generator (`generateSoundsetXml`, `elementsFromFiles`).

Soundset shape:
```
{ id, dir, name, gain, hasXml, elements: [{ id, name, kind: 'loop'|'random'|'oneshot',
  gain, randomise, files: [{name, file}], trigger: {min,max,startMin,startMax} }], moods: [...] }
```
Classification: MusicElements/LoopElements and any element with `MaxTriggerWait<=0` or negative trigger
wait → `loop`; SfxElements/MusicElements with positive trigger wait → `random`; OneshotElements →
`oneshot`. The library is cached in-process for 5s.

### 4.2 Frontend modules (`soundboard/src/`)

- `engine.js` — Web Audio. Reactive `state = { activeLoops:Set, loading:Set, activeOneshots:Set }`
  keyed by element id (a `Set` of live instances; one-shots are tracked so they can be stopped).
  Loop elements with a multi-file playlist cycle through samples, crossfading on each advance.
  API: `playLoopElement(id,{files,gain,randomise})`, `stopLoopElement(id,{fadeOut})`,
  `setLoopGain(id,v)`, `isLoopPlaying(id)`, `playOneShot(id,url,{gain})`, `stopOneShot(id)`,
  `stopAllOneshots()`, `stopAllLoops()`, `isOneShotPlaying(id)`, `setMasterGain(v)`, `stopAll()`.
- `midi.js` — unchanged Web MIDI wrapper (`connectMidi`, `onMidiMessage`).
- `store.js` — the single `reactive` state + all actions + MIDI dispatch. State: `rawSoundsets`,
  `overlay` (`{renames,hidden,addedElements,customSoundsets}`), `files`, `activeId`, `playing`,
  `masterVolume`, `elementGains` (keyed `${soundsetId}::${elementId}`), `mapping`, `learning`,
  `midiConnected`, `midiError`. `mergedSoundsets` (computed) layers the overlay over the raw scan.
  Actions: `startSoundset` (sets activeId then starts loops + randoms), `startLoops`/`stopLoops` and
  `startRandoms`/`stopRandoms` (independent sets, tracked by `store.loopsPlaying`/`randomsPlaying`),
  `stopSoundset`, `stopEffects` (`engine.stopAllOneshots`), `leaveSoundset`, `toggleSoundset`,
  `toggleLoopElement`, `playOneshotElement`, `stopOneshotElement`, `toggleRandomElement`,
  `setElementVolume`/`resetElementVolume`/`resetSectionVolume`/`isVolumeOverridden`, `setMaster`,
  `applyMood`, plus learn/`connectMidi`.
  Editor actions: `renameElement`, `hideElement`/`unhideElement`, `addElement`/`updateElement`/
  `deleteElement`, `createSoundset`/`renameSoundset`/`deleteSoundset`, `elementSource`,
  `saveOverlay`, `loadFiles`. Random elements are driven by `setTimeout` schedulers (first fire
  after `startMin..startMax`, then every `min..max` seconds).
- `App.vue` + `components/LibraryPanel.vue`, `SoundsetPanel.vue`, `ElementRow.vue`, `GroupEditor.vue`.

### 4.3 MIDI mapping format (`soundboard/midi-mapping.json`)

```json
{
  "notes": { "9:36": { "type": "oneshot", "soundsetId": "<folder>::<xml>", "elementId": "slug" } },
  "ccs":    { "1:74": { "type": "master" } }
}
```

Note actions: `{type:'oneshot'|'loop'|'random'|'soundset', soundsetId, elementId?}`. CC controls:
`{type:'master'}` or `{type:'element', soundsetId, elementId}` (element volume). The old `{type:'effect'}`
CC action is no longer used (per-element volume replaced the single global effect gain) — re-learn it.

### 4.4 Web MIDI caveats

- Requires a **secure context**: open via `http://localhost:8091` (not the LAN IP) or HTTPS.
  `connectMidi()` checks `window.isSecureContext` and surfaces a hint.
- Chrome/Edge: works out of the box. Firefox: `about:config` → `dom.webmidi.enabled=true`
  (Web MIDI isn't fully shipped in stable Firefox; Chrome/Edge is the reliable fallback).
- MPK Mini: pads send notes on channel 10, keys on channel 1, knobs send CC. "Learn mode"
  captures whatever channel/note/CC arrives, so no hardcoding needed.

## 6. Agent/LLM operational notes (things that bit us)

- **Do not `pkill -f "<string>"`** — the pattern matches the running shell's own command line and
  kills it. Use `pkill -x pocketbase` / `pkill -x node`, or `fuser -k PORT/tcp`.
- Backgrounding long-running servers in the bash tool hangs the tool until timeout. Use
  `nohup CMD </dev/null >log 2>&1 &`, then curl-test in the SAME command, then kill with
  `fuser -k PORT/tcp`. Don't rely on the process surviving across separate tool calls.
- PocketBase binary: v0.40.4, downloaded to `equipment/`, re-fetch via `equipment/download-pocketbase.sh`.
- The equipment frontend build uses `emptyOutDir` — note: `equipment/frontend/vite.config.js` writes to
  `../pb_public`. The soundboard builds to its own `soundboard/dist` (no conflict).
- `soundboard/syrinscape/` (~292MB) and runtime dirs (`equipment/pb_data/`, `soundboard/dist/`,
  `soundboard/node_modules/`, `soundboard/midi-mapping.json`, `equipment/pocketbase`) are gitignored.
- The soundboard auto-writes `<folder>.generated.xml` into any soundset folder lacking an XML file;
  these live inside `soundboard/syrinscape/` and are also gitignored. `node soundboard/generate-xml.js` does the same
  thing manually.
